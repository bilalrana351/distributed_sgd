# Detailed Concepts and Logs Explained

This document explains the hard technical terms in very basic, simple English so you can easily understand and explain them during your presentation. It also explains where our log files are saved and what is inside them.

## 1. Important Concepts Explained Simply

### What is Sync Mode (Synchronous)?
Imagine a group of students working on a group assignment. In Sync mode, everyone does their part, but before anyone can move on to the next question, they must all sit down, compare answers, and agree on a final answer. 
- **Good:** The final answer is very accurate.
- **Bad:** If one student is very slow, the whole group has to sit and wait. The fast students waste their time.

### What is Async Mode (Asynchronous)?
Now imagine the same group, but nobody waits for anyone. As soon as a student finishes a question, they hand it to the teacher and immediately start the next one.
- **Good:** It is extremely fast. Nobody waits.
- **Bad (Staleness):** A student might be solving question 5 using information from question 1, not realizing the teacher already updated the rules for question 5 based on other students' work. Their work is based on old, "stale" information, which causes mistakes (lower accuracy).

### What is a Straggler?
A straggler is just a worker (or computer) that is temporarily or permanently running slower than the others. Maybe its CPU got hot, or the network lagged. Stragglers are the main reason Sync mode becomes slow.

### What is the Hybrid Controller?
The controller is like a traffic cop. It watches the workers. If everyone is fast, it keeps the traffic light green for Sync mode (high accuracy). If it sees a slow worker (straggler), it turns the light to Async mode so the fast workers can keep driving. If it notices that the students are making too many mistakes (loss is rising), it turns the light back to Sync mode to force everyone to synchronize.

### What is Time-to-Accuracy (TTA)?
Instead of asking "How accurate is the model after 1 hour?", we ask "How many seconds does it take to reach 40% accuracy?". This is a much better way to prove that our hybrid system saves time.

## 2. Where are the Logs and What do they Contain?

All the logs generated by the code are saved in the `logs/` folder (specifically `logs/phase4_merged/` for the final results). They are saved as `.csv` (Excel) files.

Here is what the files actually contain:

### 1. `*_switches.csv`
- **What it is:** The most important file for our demo. It is the diary of the Controller.
- **What it contains:** Every time the system changes modes, it adds a line here. It tells us the exact step number, what it switched to (e.g., `0` to `1` meaning Sync to Async), and the **Reason** (e.g., `straggler_detected` or `loss_rising`). This proves the system is smart and reacting to live data.

### 2. `*_staleness.csv`
- **What it is:** The record of how "outdated" the workers were.
- **What it contains:** It tracks the "staleness" number. In Sync mode, this number is exactly 0. In Async mode, this number grows. It shows us if the Async mode was causing too much confusion for the workers.

### 3. `*_ps.csv` (Parameter Server Logs)
- **What it is:** The overall summary of the training from the boss's perspective.
- **What it contains:** It records the global step, the current validation accuracy, the global loss, and how much time has passed. This file is used to draw the accuracy graphs.

### 4. `*_worker0.csv` and `*_worker1.csv`
- **What it is:** The personal diary of each worker.
- **What it contains:** It records how long that specific worker took to complete a step. This is how the controller knows if Worker 1 is taking 3 seconds while Worker 0 is taking 1 second, meaning Worker 1 is a straggler!
